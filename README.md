# Test work

## Технічні вимоги

- Node.js 20.19+ у гілці 20 або 22.12+ у гілці 22. Перевірено на Node.js 20.19.0 та 22.13.0.
- npm (встановлюється разом із Node.js).
- Сучасний браузер із підтримкою Service Workers.
- Інтернет для встановлення залежностей і завантаження Chromium для E2E-тестів.

Усі команди виконуйте в кореневій папці проєкту. Backend і змінні середовища налаштовувати не потрібно: API імітується через MSW.

Якщо PowerShell блокує команду `npm`, використовуйте термінал Command Prompt (cmd).

## Встановлення та запуск

```sh
npm ci
npm run dev
```

Відкрийте адресу, яку покаже Vite.

## Тести та перевірки

Перевірка типів, стилю коду та unit/integration тести:

```sh
npm run typecheck
npm run lint
npm run format:check
npm test
```

Браузерні E2E-тести (Chromium встановлюється перед першим запуском):

```sh
npx playwright install chromium
npm run test:e2e
```

E2E-тести автоматично запускають локальний сервер. Перевірка реального завершення сесії триває щонайменше 30 секунд.

## Збірка та preview

```sh
npm run build
npm run preview
```

Відкрийте адресу, яку покаже Vite. Файл `dist/index.html` не потрібно відкривати напряму: застосунок потребує HTTP-сервера та Service Worker.

Для автоматичної перевірки входу через production preview:

```sh
npm run build
npx playwright test --config playwright.preview.config.ts
```

Ця перевірка автоматично запускає preview на порту **4187**; перед першим запуском також потрібен Chromium.

## Облікові дані

| Поле     | Значення           |
| -------- | ------------------ |
| Email    | `test@example.com` |
| Password | `Webhook123!`      |

Сесія діє 30 секунд і автоматично продовжується при наступному захищеному запиті. Повне перезавантаження сторінки скидає мокову сесію та зміни вебхуків — потрібно увійти повторно.

## Архітектура

React + TypeScript, Vite, React Router і TanStack Query. Сторінки поєднують UI-компоненти з API та кешем; пошук і пагінація зберігаються в URL. API-клієнт централізовано обробляє CSRF та спільну ротацію сесії для паралельних запитів, а MSW імітує backend із даними в пам'яті.

## Структура папок

```text
.
├── .vscode/          Налаштування термінала VS Code для цього проєкту.
├── public/           Статичні файли, зокрема згенерований MSW Service Worker.
├── src/              Вихідний код застосунку, точка входу, маршрути та стилі.
│   ├── api/          HTTP-клієнт, обробка помилок, CSRF, ротація та QueryClient.
│   ├── auth/         Стан користувача, вхід/вихід та стабільний fingerprint.
│   ├── components/   Форма, фільтри, таблиця, пагінація та стани інтерфейсу.
│   ├── domain/       Типи даних, валідація вебхуків і нормалізація URL-параметрів.
│   ├── mocks/        Початкові дані, MSW handlers і модель серверної сесії.
│   └── pages/        Сторінки входу, списку та редагування вебхука.
├── tests/            Unit та integration тести API, авторизації, форм і гонок сесії.
│   └── e2e/          Браузерні сценарії та перевірка входу через production preview.
├── dist/             Згенерована production-збірка після npm run build.
│   └── assets/       Зібрані JavaScript і CSS файли.
├── node_modules/     Встановлені залежності; створюється під час npm ci.
└── test-results/     Згенеровані результати Playwright і traces невдалих тестів.
```
